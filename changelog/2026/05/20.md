# [2026-05-20]

### Fixed
- fix(compose): add `extra_hosts: host-gateway` to `api` and `lab` services so containers can resolve the host machine's IP — required for local AI providers (Ollama, LM Studio) running on the host
- fix(setup): change default `base_url` for `ollama` and `lmstudio` providers from `http://localhost:…` to `http://host-gateway:…` so the setup wizard pre-fills a URL that works from inside Docker
- fix(setup): proxy model-list fetches through `POST /api/setup/models` (server-side) instead of making direct browser requests — fixes local provider reachability and avoids API keys appearing in query strings or browser history
- fix(hunts): seed the active model from `GET /api/setup` on mount instead of hardcoding `google/gemini-3-flash-preview`; remove hardcoded `DEFAULT_CHAT_MODEL` constant
- fix(projects): change `default_model` DB column default and Pydantic model default from `"google/gemini-3-flash-preview"` to `NULL` so model resolution falls through to the setup-wizard config when no project-specific model is set
- fix(db): add migration to NULL out existing `default_model = 'google/gemini-3-flash-preview'` rows so pre-existing projects also fall through to the setup-wizard model config
- fix(chat): skip API key requirement for local providers (`ollama`, `lmstudio`) — these providers require no key, so the "No API key configured" 503 error no longer fires when using them
- fix(chat): when a model returns empty content with no tool calls (model doesn't support function calling), retry the request without tools so the model can respond as plain chat instead of showing a misleading "no tools available" notice
- feat(chat): extract model chain-of-thought reasoning (`<|channel>thought...<channel|>` blocks) and `<tool_code>` pseudo-code from streamed responses server-side; stream is buffered silently and a `replace` event delivers clean content + separate `thinking` field to the UI
- feat(ui): render model thinking blocks as collapsible "💭 Thinking" sections above the assistant response; thinking persists in DB and is shown on history reload

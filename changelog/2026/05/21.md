# [2026-05-21]

### Added
- feat(chat): introduce LiteLLM-backed chat v2 — `chats_ai_v2.py` replaces the hand-rolled `httpx` dual-format provider layer with `litellm.acompletion()`, giving unified routing across OpenRouter, Anthropic, Gemini, Ollama, LM Studio, and 100+ other providers without manual format branching
- feat(chat): new streaming endpoint `POST /api/v2/chats/{session_id}/messages/stream` (`chats_v2.py`) — identical SSE wire format to v1 so the frontend requires no other changes; tool execution, session persistence, and streaming subprocess runners are unchanged
- feat(ui): new `/hunts-v2` page wired to the v2 stream endpoint; accessible via "Hunts v2" sidebar nav item; all existing hunt sessions, tools, and workspace files are shared with `/hunts`
- chore(deps): add `litellm==1.67.0` to `requirements.txt`

### Fixed
- fix(chat): `_extract_thinking` now handles both `<|channel>thought\n...\n<channel|>` variants (with and without trailing newline before closing tag) and separates multiple thinking blocks with `---` so each segment is visually distinct in the ThinkingBlock UI
- fix(chat): add `extract_nonstandard_tool_calls()` — parses `<|tool_call>call:name{...}<tool_call|>` tags emitted by local models (e.g. Kimi/Moonshot via LM Studio) that do not honour the OpenAI function-calling schema; wired into both v1 (`chats.py`) and v2 (`chats_v2.py`) streaming loops as a fallback when no structured `tool_calls` are returned
- fix(chat): strip hallucinated `[TOOL_RESULT]...[END_TOOL_RESULT]` blocks that some local models inject inline into their response text
- fix(chat): extend non-standard tool call parser to handle Gemma 4 E4B format — unclosed `<|tool_call>` blocks terminated by `[END_TOOL_REQUEST]` instead of `<tool_call|>`, and `<|"|>` quote escapes in argument values; stray `[END_TOOL_REQUEST]` markers are now stripped from visible content
- fix(ui): redesign `ThinkingBlock` to match tool-row style — full-width collapsible row with `MessageCircle` icon, collapsed by default, rendered as a peer row above the AI bubble rather than nested inside it; applies to both persisted messages and live streaming state
- fix(db): persist `thinking` field in `chat_messages` table — add `thinking TEXT` column (with migration for existing DBs), write it in `save_chat_messages`, read it back in `get_chat_messages`; fixes thinking rows disappearing when navigating away and returning to a hunt
- fix(ui): suppress blank AI bubble when assistant message has thinking but no visible content — render `ThinkingBlock` standalone instead of wrapping an empty bubble
- fix(setup): `GET /api/setup` now resolves the actual loaded model for local providers — when the stored model is the `"local-model"` placeholder, queries LM Studio's `/v1/models` (or Ollama's `/api/tags`) and returns the first real model ID so the UI context header shows the true model name
- fix(chat): raise default `max_tool_calls` from 10 → 20; emit a `notice` SSE event (and persist it in the DB) when the tool call limit is reached so the user sees a clear message instead of the chat silently stopping; add `notice` event handler in the frontend streaming loop
- feat(chat): add token usage display in the context panel — `↑ prompt ↓ completion` tokens shown next to Cost after each exchange; backend accumulates usage across all tool-call iterations and includes it in the `done` SSE event; supported by both v1 (OpenAI SSE `usage` field) and v2 (LiteLLM usage dict)
- fix(ui): model selector now scoped to configured provider — `POST /api/setup/models` accepts an empty body and falls back to the stored provider/key/base_url so the picker shows LM Studio, Ollama, or other provider models instead of always listing OpenRouter; `SetupConfig.provider` made optional to support this
- feat(ui): promote `/hunts-v2` to `/hunts` — LiteLLM-backed stream endpoint (`/api/v2/chats/…`) is now the default; old `/hunts-v2` route and "Hunts v2" nav entry removed; `/hunts-v2` directory deleted
- fix(chat): correct misleading "no tools available" message in `chats_v2.py` — the empty-response fallback now distinguishes between `enabled_tools=[]` (tools disabled → show tools panel hint) and a genuinely empty model response (tools enabled → show "model returned empty response, try rephrasing" hint)
- feat(ui): include `provider` in hunt export JSON — `exportChat` now captures provider from `GET /api/setup` and writes it alongside `model` and `session` in the downloaded file
- fix(chat): fix empty responses from OpenRouter/Gemini models in `stream_ai_completion` — replaced hardcoded `finish_reason` allowlist with `bool(finish_reason)` check so any non-None/non-empty finish reason triggers the final yield; safety fallback now yields accumulated text instead of empty string so content is never silently dropped
- feat(infra): add `docker-compose.prod.yml` — pulls pre-built GHCR images (`ferret-api`, `ferret-ui`, `ferret-docker-shim`); `just up` now uses this for stable production installs without requiring a build step
- feat(infra): add `.github/workflows/publish-release.yml` — builds and pushes all three service images to GHCR on version tag push (`v*`), tagged `:latest` and `:<version>`
- feat(infra): API hot reload in dev — `docker-compose.yml` now mounts `src/apps/api` over `/app` and runs uvicorn via `watchfiles` so Python changes auto-restart the server without a rebuild; `just dev` updated to reflect this
